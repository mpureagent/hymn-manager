关键核对：

- 投屏渲染**只调用** `shared/style.ts` 的 `styleToCssVars()` 写 CSS 变量，没有第二套换算；预览与投屏使用同一变量名。
- 样式变更只重设根元素 CSS 变量，不重建投屏歌词 DOM。
- 所有跨进程内容都先过 `normalizeProjectionContent()`：书/编号非法返回 null，样式经 `clampStyle()`，行内容去空并限长。
- 分页：**一段一页**，因此 4 段歌稳定为 1/4–4/4；无歌词时显示「本首歌词暂缺」。
- 单屏时 `chooseProjectionDisplay()` 回落主屏并返回提示文案；双屏优先非主屏，能记住上次显示器。
- 主窗关闭 → 主进程关闭投屏窗口，应用退出，无残留进程。

## 四、过程中发现并修复的问题

**投屏全屏遮挡主窗时，主窗计时器被 Chromium 后台节流。**
现象：投屏后立即在主窗输入检索，120ms 防抖被延迟到数秒后触发，晚于用户点行，导致预览被清空、`currentItem` 丢失，F5 会提示「请先选择一首诗」。
处置：主窗 `webPreferences.backgroundThrottling: false`；验收脚本也改为等检索结果真正出现再点行。修复后 102 例测试无一回归。
